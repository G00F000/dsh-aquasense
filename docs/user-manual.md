# dsh-aquasense 使用手册

## 1. 系统简介

dsh-aquasense 是水产养殖 AI 巡检系统，服务于鲈鱼循环水养殖场景。工人通过飞书发送文字和照片，AI 自动完成:

- **健康诊断**: 识别鱼群状态（正常 / 前兆 / 发病）
- **处置建议**: 基于知识库生成分级处置方案
- **台账登记**: 自动将巡检记录写入飞书多维表格

### 适用场景

| 编号 | 场景 | 说明 |
|------|------|------|
| S1 | 水质汇报 | 汇报溶氧、氨氮、pH 等水质指标 |
| S2 | 日常巡检 | 拍照汇报鱼群状态（默认场景） |
| S3 | 知识询问 | 咨询养殖相关问题 |
| S4 | 死亡汇报 | 发现死鱼时紧急汇报 |
| S5 | 用药记录 | 记录药品使用情况 |
| S6 | 喂食记录 | 记录投喂量和摄食情况 |
| S7 | 温度汇报 | 汇报水温、棚温 |
| S8 | 解剖记录 | 记录鱼体解剖检查结果 |
| S9 | 每日提醒 | AI 定时推送当日巡检任务 |

## 2. 快速开始

### 2.1 给 AI 发消息

在飞书巡检群中，直接向 AI 机器人发送文字或照片:

**发送照片（自动识别为巡检）**:

```
[拍照] 池3 鱼群状态
```

**发送文字汇报**:

```
池2 水质:溶氧5.2 氨氮0.1 pH7.4
```

**发送紧急报告**:

```
池1 死了3条鱼，浮在水面
```

### 2.2 AI 回复示例

**巡检回复**:

```
池3 巡检结果
- 状态: early（前兆）
- 症状: 离群独游、呼吸急促
- 严重程度: medium
- 建议:
  1. 减料 50%
  2. 密切观察 24 小时
  3. 检测溶氧、氨氮
- 台账已记录 ✓
```

**死亡汇报回复**:

```
⚠️ 池1 死亡报告 - P1 预警
- 状态: disease（发病）
- 死亡数量: 3 条
- 建议: 立即通知负责人，隔离病鱼，紧急检测水质
- 台账已记录 ✓
- 请通知场长
```

## 3. 各场景使用指南

### 3.1 S1 水质汇报

**发送方式**: 文字 + 照片（可选）

```
池2 水质:溶氧5.2 氨氮0.1 pH7.4 亚硝酸0.02
```

**包含照片时**: AI 会自动分析水色并补充建议。

**台账字段**: 池号、检测时间、溶氧(mg/L)、氨氮(mg/L)、pH值、亚硝酸盐(mg/L)、水色描述、AI分析。

### 3.2 S2 日常巡检（默认）

**发送方式**: 拍照 + 文字描述

```
[拍照] 池4 有几条鱼蹭壁
```

**AI 自动处理**:
1. 分析照片，判断鱼群状态
2. 查询知识库获取相关建议
3. 写入巡检台账

**三分类说明**:

| 分类 | 含义 | AI 行为 |
|------|------|---------|
| normal | 正常 | 仅登记台账 |
| early | 前兆（12-48h 领先信号） | 提示预防措施，加强观察 |
| disease | 发病 | 紧急建议 + 预警通知 |

### 3.3 S3 知识询问

**发送方式**: 纯文字提问

```
鲈鱼白点病怎么预防？
```

**AI 回复**: 基于知识库查询结果回答，**不会**写入台账。

### 3.4 S4 死亡汇报（紧急）

**发送方式**: 文字 + 照片（可选）

```
池3 死了2条鱼，翻白了
```

**AI 自动处理**:
1. 状态优先级最高，立即响应
2. 如有照片则分析死鱼状态
3. 生成紧急处置建议
4. 写入死亡记录表
5. 提醒通知负责人

**注意**: 死亡场景会触发 P0/P1 预警，AI 会在回复中提醒 @负责人。

### 3.5 S5 用药记录

**发送方式**: 文字 + 照片（可选）

```
池2 用了200ml 聚维酮碘消毒
```

**台账字段**: 池号、用药时间、药品名称、用药剂量、用药方式、用药原因。

### 3.6 S6 喂食记录

**发送方式**: 文字

```
池1 喂了25kg 饲料，摄食正常
```

**台账字段**: 池号、喂食时间、饲料种类、投喂量(kg)、摄食情况。

### 3.7 S7 温度汇报

**发送方式**: 文字

```
池4 水温26度 棚温28度
```

**台账字段**: 池号、测量时间、水温(℃)、棚温(℃)。

### 3.8 S8 解剖记录

**发送方式**: 文字 + 照片（可选）

```
池2 解剖了一条，肝脏发白，胆囊肿大
```

**AI 自动处理**:
1. 分析解剖照片（如有）
2. 查询知识库获取疾病参考
3. 写入解剖记录表

### 3.9 S9 每日任务提醒

S9 由系统自动运行，无需工人主动发送消息。

**工作方式**:
- 每天 07:00 在巡检群推送当日任务总览
- 到任务时间点推送单条提醒（如 08:00 投喂、10:00 巡检等）
- 提醒中包含"今日剩余任务"预览

**任务来源**: IMA 知识库中的《每日操作手册》，格式为:

```
07:00 开启增氧机，检查水质
08:00 投喂早餐，记录投喂量
10:00 巡检各池鱼群状态
14:00 投喂午餐
16:00 下午巡检，检测水质
18:00 投喂晚餐
20:00 夜间巡检准备
```

**收到提醒后**: 按平时格式发消息汇报即可，AI 会自动识别场景并登记台账。

## 4. 消息发送规范

### 4.1 池号必须包含

每条消息务必包含池号信息，否则 AI 会追问:

- 正确: `池3 有几条鱼离群`
- 正确: `[拍照] 池2 水质`
- 错误: `有几条鱼离群`（缺少池号）

### 4.2 口语化表达

AI 能理解口语化表达，无需刻意使用专业术语:

| 你说的 | AI 理解为 |
|--------|-----------|
| 溶养 | 溴氧 |
| 蔫了/没精神 | 活动减少 |
| 死了2条 | 死亡数量: 2 |
| 白花花的 | 白点症状 |
| 翻肚子了 | 侧翻失衡 |

### 4.3 多信息混发

一条消息中包含多个场景的信息时，AI 会自动拆分并分别登记:

```
池3 水温26度，喂了20kg
```

→ AI 会写入两条记录: 温度表 + 喂食表。

### 4.4 照片建议

- 拍摄鱼群全景 + 局部特写
- 光线充足，避免逆光
- 如有死鱼，拍摄全身和局部特写
- 照片越清晰，AI 诊断越准确

## 5. 预警级别说明

| 级别 | 含义 | 触发条件 | 行为 |
|------|------|----------|------|
| P0 | 最高预警 | disease + critical | 立即通知负责人，紧急处置 |
| P1 | 高预警 | disease 或 severity=high | 通知负责人，加强巡塘 |
| P2 | 一般关注 | 其他异常 | 记录观察，正常处置 |

---

## 6. 台账查看

所有巡检记录自动写入飞书多维表格，可在飞书中直接查看:

1. 打开飞书「多维表格」应用
2. 找到「水产养殖台账」表格
3. 按场景切换不同数据表（巡检、水质、用药等）
4. 可按池号、时间、状态等条件筛选和排序

**台账仅追加不修改**，满足政府 2 年养殖台账审计要求。

## 7. 常见问题

### Q1: 发了消息但没有回复

可能原因:
- 飞书机器人未正确配置（联系管理员检查 dsh-lark 插件）
- DeepSeek API 额度不足（联系管理员检查 API Key）
- 消息未被识别（尝试包含关键词或发送照片）

### Q2: 台账写入失败

可能原因:
- 表格列名不匹配（联系管理员检查列名）
- 飞书应用权限不足（联系管理员检查 `bitable:app` 权限）
- 池号缺失（AI 会追问，补齐即可）

### Q3: AI 诊断结果不准确

建议:
- 提供更清晰的照片
- 补充文字描述具体症状
- 多次观察确认后再汇报
- AI 标注"待确认"时，需人工复核

### Q4: S9 提醒没有推送

联系管理员检查:
- `FEISHU_WORKER_GROUP` 是否配置
- 飞书应用是否加入巡检群
- IMA 知识库中是否有《每日操作手册》

### Q5: AI 用药建议是否可以直接使用

**不可以。** AI 提供的用药建议仅基于知识库参考，**必须咨询专业兽医确认后方可用药**。AI 不代替兽医开药方。

---

## 8. 注意事项

1. **AI 不是兽医**: 处置建议仅供参考，疾病治疗须咨询专业兽医
2. **池号务必填写**: 缺少池号的记录不会被写入台账
3. **照片尽量清晰**: 图片质量直接影响诊断准确率
4. **紧急情况优先**: 死亡汇报（S4）具有最高优先级，AI 会立即响应
5. **台账不可篡改**: 记录一旦写入无法修改，确保汇报内容准确
6. **手册格式规范**: 《每日操作手册》需按 `HH:MM 任务` 格式编写，每行一条
