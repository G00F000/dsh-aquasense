## 1. 背景与动机

### 1.1 现状问题

AquaSense 的 AI 分析管线（图片 → 视觉分析 → 知识库检索 → 处置建议 → 台账写入）已完整运行，但存在以下可观测性缺口：

| 问题 | 影响 |
|------|------|
| 分析结果仅在飞书群聊中回显 | 工人无法回溯历史分析，管理者无法全局查看 |
| 每步耗时、Token 消耗无记录 | 无法定位性能瓶颈（视觉模型慢？知识库慢？） |
| 知识库命中来源不透明 | 无法验证 AI 建议的知识库依据是否充分 |
| 无趋势分析能力 | 无法发现"某池反复出现前兆"等规律 |

### 1.2 设计目标

- **全流程可视化**：每次分析的 5 个步骤（上传 → 视觉分析 → 知识库检索 → 处置建议 → 台账写入）均有完整记录
- **每步可追溯**：输入、输出、耗时、Token 消耗、错误信息全部落盘
- **知识溯源**：AI 处置建议的每条知识引用均可追溯到源文档（PDF 页码、笔记标题）
- **趋势分析**：按池号、时间段查看分析结果的语义分布和趋势变化
- **PC 端统一查看**：分析记录与详情统一在 PC 端配置页面板（入口 C）查看，屏幕大、信息密度高；移动端（飞书 H5）仅保留拍照汇报与「提交成功」反馈

### 1.3 设计约束

- **环境**：4 核 4G 服务器，零额外依赖（不引入 MySQL/Redis/ClickHouse）
- **存储**：JSON 文件（`$AQUASENSE_CACHE_DIR/remind/reports/`），与现有 S9 缓存目录共用
- **前端**：纯 HTML + Vanilla JS + CSS Variables，无框架依赖，无构建步骤
- **规模**：4 池 × ~20 次/天 ≈ 200 条/月，JSON 文件完全可承载
- **复用**：复用现有 `remind-gateway.ts` 的 HTTP 服务和路由注册机制

## 3. 页面入口设计

### 3.1 两个入口

| 入口 | 位置 | 目标页面 | 触发方式 |
|------|------|----------|----------|
| **入口 A** | H5 拍照汇报页提交后 | 提交成功反馈（无后续展示） | 提交成功后仅展示成功反馈，不跳转 |
| **入口 C** | AquaSense 配置页顶栏页签区，「每日任务提醒」右侧页签「📊 分析记录」 | 分析记录页（列表态 ⇄ 详情态，面板内嵌；PC 端唯一查看入口） | 点击页签 → 面板内容区同页切换（React 组件直调 API，不新开页面） |

> **入口 C 设计注（v1.1）**：入口 C 由配置页内的独立按钮改为并入顶栏二级标题区、以页签形式呈现（样式对齐 SkillHub 插件广场二级标题的「插件 / 技能」页签）：「每日任务提醒」为当前页签，右侧并列「📊 分析记录」页签，点击在面板内同页切换展示列表页；右上角 × 关闭按钮保持不变。实现落点：`src/client/AquaConfig.tsx` 顶栏（`.aqs-top`）。

> **入口 C 内嵌注（v1.2→v1.3）**：点击「📊 分析记录」页签不再新开标签页——v1.2 曾用 iframe 内嵌 `/aquasense-reports` 页面，但部署环境存在跨域/反向代理路径不通问题（iframe 请求被拒绝连接），v1.3 改为面板内 React 组件（`TraceRecordList`）直接调 `/aquasense-reports/api/records` JSON API 渲染列表；页签组以 `role="tablist"` + `aria-selected` 呈现（对齐 SkillHub「插件 / 技能」）；首次切换才挂载、切换用 display 保持表单草稿与列表状态；列表内点击记录可在面板内查看详情。实现落点：`src/client/TraceRecordList.tsx` + `src/client/AquaConfig.tsx`（`.aqs-reports` / `.aqs-body.flush`）。

> **入口精简注（v1.4）**：原「入口 B」（飞书卡片「查看详情」按钮 → `/aquasense-reports/report?id=RPT-xxx`）整体移除——卡片按钮 + URL 跳转链路过于繁琐，飞书侧不再提供分析详情入口；详情查看统一经入口 A（H5 提交成功后自动跳转）与入口 C（配置页「📊 分析记录」页签 → 面板内列表 → 面板内详情）。

> **入口归并注（v1.6）**：入口 A 不再跳转/展示分析详情——H5 提交成功后仅展示「提交成功」反馈（不含结果明细、5 步进度等附加内容）；分析记录与详情的查看统一到入口 C（PC 端配置页面板）进行，移动端不再承载任何查看界面。

```
┌─────────────────────────────────────────────────────────────┐
│  每日任务提醒   📊 分析记录                            ×    │
├─────────────────────────────────────────────────────────────┤
│  ▸ 「每日任务提醒」= 当前页签（S9 提醒配置表单）              │
│  ▸ 「📊 分析记录」= 入口 C（点击面板内同页切换展示）           │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 URL 路由

> **展示归并注（v1.6）**：分析记录的展示统一在入口 C 面板内（React 组件直调 JSON API，见 §6.2），不再要求独立的列表/详情浏览页面——原 `GET /aquasense-reports`（列表态）与 `GET /aquasense-reports/report?id=RPT-xxx`（详情态直达）两条页面路由不再启用。

| 路由 | 页面 | 说明 |
|------|------|------|
| `GET /aquasense-reports/trend?pool=池3` | 池号趋势页 | 按池号查看语义分布和趋势（列表态底部入口跳转） |

- 整页布局：左侧一级导航栏（「智慧渔业」高亮选中）+ 右侧内容区

- 瀑布图：5 个步骤的时间轴可视化，颜色编码（上传=灰色，视觉=蓝色，检索=橙色，建议=绿色，台账=紫色）
- 步骤 Accordion：点击任意步骤展开/折叠详情
- 每步详情包含完整的 Input/Output/耗时/Token
- 知识库检索步骤特别展示：查询词、三通道命中数、合并结果、命中条目详情（含高亮原文/页码）
- 图片缩略图：工人发送的原始图片在详情态「现场照片」区以缩略图网格展示（元信息区下方），点击缩略图打开灯箱预览（支持左右切换/点击关闭）；图片由服务端落盘缓存目录并经 `api/records/:id/images/:index` 提供
- 内容区右侧有滚动条，`▲` 表示上方还有未展示的内容

**状态切换（v1.5 合并）**：
- 列表态点击任意记录 → 详情态；详情态「← 返回」→ 列表态（同页切换，不新开页面）
- 本原型由入口 C 面板（PC 端）承载；H5 侧提交后仅「提交成功」反馈，不跳转、不展示详情
- 返回列表态时保留筛选条件与已加载记录

## 5. 数据模型

### 5.1 AnalysisRecord（单条分析记录）

```typescript
interface AnalysisRecord {
  /** 报告唯一 ID，格式 RPT-YYYYMMDD-HHmmss */
  id: string
  /** 池号: 池1/池2/池3/池4 */
  pool: string
  /** 上报人飞书姓名 */
  reporter: string
  /** 上报人 open_id */
  reporter_open_id: string
  /** 来源: 'h5_upload' | 'group_chat' | 'api' */
  source: 'h5_upload' | 'group_chat' | 'api'
  /** 任务描述（S9 提醒场景） */
  task?: string
  /** 群 ID（关联 S9 提醒卡片） */
  chat_id?: string
  /** 创建时间 ISO 8601 */
  created_at: string

  /** ---- 元信息 ---- */
  model: string              // 使用的视觉模型名
  total_duration_ms: number  // 总耗时
  total_tokens: number       // 总 Token 消耗

  /** ---- Span: 图片上传 ---- */
  span_upload: {
    image_count: number        // 图片数量
    image_sizes: number[]      // 原始大小(bytes)
    compressed_sizes: number[] // 压缩后大小(bytes)
    duration_ms: number        // 耗时
    error?: string             // 错误信息(如有)
  }

  /** ---- Span: AI 视觉分析 ---- */
  span_analyze: {
    prompt_length: number      // Prompt 字符长度
    input_tokens: number       // 输入 Token
    output_tokens: number      // 输出 Token
    duration_ms: number        // 耗时
    output_raw: string         // 模型原始输出(截断保留前500字)
    /** AnalysisResult 核心字段（从 parseAnalysisResponse 提取） */
    cls: 'normal' | 'early' | 'disease' | 'unknown'
    symptoms: string[]
    severity: string
    confidence: number
    scene_hint: string
    error?: string
  }

  /** ---- Span: 知识库检索 ---- */
  span_retrieve?: {
    query: string              // 搜索关键词
    channel_a_wiki: number     // wiki 命中数
    channel_b_note: number     // note 命中数
    channel_c_pdf: number      // PDF 命中数
    merged_count: number       // 合并去重后条数
    excerpts: Array<{
      title: string            // 文档标题
      from: string             // 来源通道(pdf_content/note/wiki)
      locator?: string         // 定位(如"第56页")
      excerpt_preview: string  // 引用原文预览(前100字)
    }>
    duration_ms: number
    error?: string
  }

  /** ---- Span: 处置建议生成 ---- */
  span_advice?: {
    input_cls: string          // 输入的分类
    alert_level: string        // 预警级别 P0/P1/P2
    knowledge_refs_count: number // 知识库参考来源数
    diagnosis_summary: string  // 诊断摘要
    reasoning_preview: string  // 推理过程预览(前200字)
    duration_ms: number
    error?: string
  }

  /** ---- Span: 台账写入 ---- */
  span_ledger?: {
    target_table: string       // 目标表名
    operation: 'create' | 'update'  // 操作类型
    record_id?: string         // 飞书 Bitable 记录 ID
    duration_ms: number
    error?: string
  }
}
```

### 5.2 index.json（分析记录索引）

```typescript
interface AnalysisIndex {
  version: 1
  records: Array<{
    id: string
    pool: string
    reporter: string
    source: string
    cls: string
    confidence: number
    symptoms: string[]
    alert_level?: string
    created_at: string
    total_duration_ms: number
  }>
}
```

**设计要点**：
- `records` 按 `created_at` 倒序排列
- 仅保留轻量摘要字段，避免列表态加载时读取全部 JSON 文件
- 单条记录完整数据在 `reports/RPT-*.json` 中

## 6. API 设计

### 6.1 记录创建（服务端内部调用）

每次 AI 分析管线执行完成后，自动调用：

```
内部函数: recordAnalysis(record: AnalysisRecord)
    → 写入 reports/RPT-YYYYMMDD-HHmmss.json
    → 更新 index.json（在头部插入）
```

### 6.2 查询 API

| 方法 | 路由 | 参数 | 说明 |
|------|------|------|------|
| GET | `/aquasense-reports/api/records` | `?pool=&cls=&date=&limit=&offset=` | 列表查询 |
| GET | `/aquasense-reports/api/records/:id` | — | 单条详情 |
| GET | `/aquasense-reports/api/trend/:pool` | `?days=7` | 池号趋势统计 |

**列表查询响应**：

```json
{
  "ok": true,
  "value": {
    "records": [ /* index.json 中的摘要字段 */ ],
    "total": 42,
    "has_more": false
  }
}
```

**详情查询响应**：

```json
{
  "ok": true,
  "value": { /* 完整 AnalysisRecord */ }
}
```

**趋势统计响应**：

```json
{
  "ok": true,
  "value": {
    "pool": "池3",
    "total": 20,
    "distribution": { "normal": 17, "early": 2, "disease": 1 },
    "top_symptoms": [{ "symptom": "蹭壁", "count": 4 }],
    "recent_records": [ /* index.json 摘要，最多10条 */ ]
  }
}
```

## 7. 前端技术选型

| 维度 | 选型 | 理由 |
|------|------|------|
| 框架 | 面板内 React 组件（分析记录查看）+ 无框架 Vanilla JS 单页面（趋势页） | 分析记录复用 DSH 客户端运行时与面板组件体系；趋势页零依赖、随插件 Web 服务托管 |
| 样式 | CSS Variables + `prefers-color-scheme` | 跟随系统暗色/亮色主题，复用 DSH 设令牌 |
| 图表 | 纯 CSS 柱状图 + 简单 Canvas 散点图 | 无需引入 Chart.js 等库，保持轻量 |
| 布局 | CSS Grid + Flexbox | 响应式（查看端以 PC 为主，宽窄屏自适应） |
| 路由 | 面板内状态切换（列表态 ⇄ 详情态） | 展示统一入口 C 面板内，无独立页面路由依赖 |
| 交互 | CSS `details/summary` + Transition | Accordion 折叠展开，原生 HTML 语义 |

## 8. 交互流程

### 8.1 H5 提交后的反馈流程（v1.6 精简）

```
工人在 H5 上传页点击「完成汇报」
    │
    ▼
图片上传 → 服务端接收并启动分析管线（后台异步执行）
    │
    ▼
展示「提交成功」反馈（✓ 已提交；不跳转、不展示分析结果与进度明细）
    │
    ▼
（结束）分析结果与详情统一到入口 C 查看：
PC 端「智慧渔业 → 📊 分析记录」面板内列表态 ⇄ 详情态
```

**交互说明（v1.6）**：
- 「提交成功」为唯一反馈（成功图标 + 一句话），不跳转、不展示 5 步进度与结果明细
- 上传失败/提交异常时仍展示失败提示与「重新汇报」，不静默丢失
- 结果查看入口仅在 PC 端入口 C（面板内）

### 8.2 列表态 → 详情态流程（同页切换）

```
管理者打开分析记录页（列表态）
    │
    ▼
GET /aquasense-reports/api/records?limit=50
    │ → 返回 index.json 摘要列表
    ▼
按日期分组展示，状态颜色编码
    │ → 筛选器：池号 / 状态 / 时间范围
    ▼
点击某条记录（同页切换至详情态）
    │
    ▼
GET /aquasense-reports/api/records/RPT-20260917-1005
    │ → 返回完整 AnalysisRecord
    ▼
渲染 Trace 视图（瀑布图 + 步骤 Accordion）
    │ → 知识库检索步骤展示命中条目详情
    ▼
底部「查看趋势」→ 跳转池号趋势页
```

## 9. 容错与约束

| 故障场景 | 降级行为 |
|----------|----------|
| records 目录不存在 | 创建空目录 + 空 index.json |
| 单条记录 JSON 损坏 | 列表态跳过该条，日志 warn |
| index.json 损坏 | 从 reports/ 目录扫描重建 |
| 查询参数非法 | 返回 400 + 错误描述 |
| 图片缩略图文件丢失 | 显示占位图 |
| 记录数超过 1000 条 | index.json 仍可承载（~300KB），不阻断 |
| 趋势页数据不足 | 显示"数据不足，至少需要 3 条记录" |
